# 延迟与速度档

TCL V064的当前后端是硬件逐点查询，每点约30ms。九区各一点需要约270ms，不能把速度档的目标值当作所有区域同时刷新的帧率。

流畅档在首轮完整初始化后，每取完三个区域立即发送完整灯带帧。区域顺序分散到屏幕周围，未刷新区域保留自己的上一轮颜色。九区均独立采样，没有用三种颜色复制成九区。每个区域仍需等待约一轮才能再次刷新；同一输出包含不同采样时刻的颜色。这种取舍适用于逐点后端，全帧后端保持同帧采样。

| 测量项 | 旧原型 | v110／frame-luma-4 |
| --- | --- | --- |
| 常规完整帧发送间隔 | 约269ms | 分批约90ms |
| 一轮开始到首批发送完成 | 等待完整九区 | 约90ms，首轮初始化除外 |
| 九区完整轮换 | 约269ms | 约270ms |
| USB发送及同步检查 | 每帧等待回包 | 约3–4ms；回包移到独立阻塞线程 |

以上是软件采样和USB发送完成的测量，包含正常调度抖动。它不是摄像机测得的画面变化到灯带发光的端到端延迟，也不表示每个区域已达到每秒十次刷新。

流畅档目标150ms，当前九点接口取色超过此值时立即进入下一轮，不额外等待。均衡和节能分别以500ms、1000ms为整轮目标，整轮发送后只等待剩余时间。切换档位在线生效。高级设置每区三点意味着27次查询，精度与延迟需要取舍。

预览仅在界面可见时最多每250ms报告一次，后台不逐帧写日志、图片或配置。颜色留在内存；设置变化才写应用私有偏好。USB线程与采样线程在关闭／强停时释放，不需要重启清缓存。

## 复测

在匹配设备连接好灯带并开启随影后，从仓库根目录执行：

```sh
python devices/displays/tcl-ffalcon/realtek/m01-g10/27c2a-s/tools/measure_latency.py --serial <ADB设备地址>
```

默认测量8秒，只请求受限的状态操作，不修改设置、不清日志，也不在电视上写测量文件。报告保存在电脑`.local/latency.json`。其它品牌的设备诊断工具应放在自己的型号目录。

默认测量`device`来源，先退出映光页面进入DP。测自身界面时添加`--source own_app`，避免把App内存画面约150ms的完整更新与TCL硬件九点约270ms混为一项。页面本身的自适应和来源切换见[界面说明](interface.md)。

离线`ZoneSamplerTest`使用每点30ms的确定性后端复现等待：旧的整轮后输出在270ms才首次发送，分批版本在90ms即可首次发送。测试还覆盖首轮完整初始化、同帧后端和取消后的停止输出；USB测试覆盖跨包错误及握手完整响应。
